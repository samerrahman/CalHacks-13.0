# Tracks, schedule and judging evidence

## Strongest entry plan

These are fit assessments against the user-provided rubric, not predictions of winning or confirmed prize eligibility.

| Track | Meaningful implementation | What to demonstrate |
|---|---|---|
| Presage | Real camera pulse, quality handling, personal baseline and bounded tactic adaptation | Live metric with freshness; a decision using its trend; camera-loss fallback |
| ElevenLabs | Boss and imitation speech share a voice; state changes generate a new spoken request | Hear a current, context-specific line and verify it against independent evidence |
| Gemini API | Director selects tactics using action history and legal options | Two different histories produce relevant, legal choices; invalid output is rejected |
| Convex | Reactive session events, scheduled provider work, synchronized judge view and replay | Game action appears live on second screen; reconnect does not duplicate an encounter |
| Gen AI | Same functioning adaptive director and generated speech | Explain concrete effects on gameplay, not just a chat interface |
| Most Creative / Hacker's Choice | A familiar voice exploits what you tend to do | A judge hears a plausible instruction, finds its tell, and survives |
| Most Technically Complex | Sensor, native IPC, asynchronous AI/audio, deterministic simulation and replay | One complete end-to-end trace with failure handling |

With a polished core, there are five natural sponsor categories plus relevant overall awards. That is a more credible target than claiming every sponsor. Check event rules on submission limits and overlapping entries; the pasted listing does not settle those questions.

## Optional, only after the core works

Cartesia can support an interruptible supervisor conversation. Backboard can remember gameplay habits across runs. A real deployment on Vultr or DigitalOcean can qualify for that provider if it actually hosts a necessary component; merely mentioning a provider does not count. Notability can capture sketches, decisions, annotations and recorded playtests throughout development. Mana is only a claim if actually used and its required public build/chat links are supplied.

Meta is a weak fit for a single-player game; an NPC is not by itself meaningful human connection. Microsoft's high-impact production-agent rubric is also a weak match. Do not pitch a horror game as healthcare or therapy to force those prizes. Finance, credit, shopping, space-data and security categories do not naturally fit this design. Factory requires Droid inside the running product: using Codex or a coding assistant to build it is not enough. SpacetimeDB is an alternative to Convex for a future shared-game design, not an extra checkbox. The unknown/TBD tracks need actual rules before making claims.

## 48-hour implementation order

| Time | Deliverable | Exit condition |
|---|---|---|
| 0–2 h | Presage feasibility + asset import | Real pulse on the target laptop; imported GLBs animate |
| 2–10 h | Offline playable shift | Tasks, doors, power, one creature, verification, win/loss |
| 10–18 h | Sound, readable clues, lighting, tutorial | A new tester understands how to survive |
| 18–26 h | Gemini and ElevenLabs live path | Real adaptive proposal + real generated line; timeout fallback |
| 26–32 h | Presage in game + Convex trace | Sensor trend influences bounded choice, live second-screen evidence |
| 32–40 h | Balance and integration failure checks | Several seeded wins; camping fails; camera/API loss handled |
| 40–48 h | Demo, README, attribution, bug fixes | Rehearsed two-minute demo, recorded backup, clear integration status |

For a team: one person owns game/rules, one native sensing/integrations, one art/audio/UX, one backend/demo/testing. If solo, omit optional memory/voice chat and simplify Convex to event feed + provider actions. Codex still needs playtest feedback and keys; do not expect a single unattended prompt to produce final game feel.

Cut order if late: optional sponsors, generated visual polish, full replay UI, extra dialogue variants, complex postprocessing. Preserve real sensing, a functioning task loop, one valid spoof, one legal attack and honest status labels. If the native SDK fails, keep the playable game and report that the Presage integration is incomplete; do not substitute a slider while claiming the track.

## Two-minute judge sequence

Calibration occurs before the timed presentation. Use a named demo scenario with compressed task durations and the same gameplay rules. A fixed seed ensures teachable events; clearly identify this as a demonstration scenario, not evidence that every decision was generated live.

0:00–0:15: Show real measurement status and quality. One sentence: "It can copy your supervisor's voice and adapt its tactics to your actions and measured pulse trend."

0:15–0:40: Complete a genuine order. Close both doors briefly and show task progress stops / power drains, then reopen the clear side. The judge sees why camping is not the game.

0:40–1:10: Hear a plausible fake. Inspect its expired ID or request the challenge response. Reject it. Close the threatened side; complete a safe task on the other side. Do not reveal the fake with a red label before the judge verifies it.

1:10–1:35: Show the actual director trace: observed recent actions, accepted pulse trend or UNKNOWN, allowed tactic set, returned choice and applied outcome. A physiological reaction is not guaranteed on demand. If live pulse stays stable, demonstrate that valid stable condition honestly. A separate explicitly labeled replay or simulated comparison can explain the alternate branch without being presented as live sensing.

1:35–1:50: Complete final upload while the creature is in a genuine safe window. Show live Convex event on a second screen.

1:50–2:00: Cover/stop the camera to show UNAVAILABLE and a playable neutral fallback. End on the completed shift or replay trace.

## Evidence checklist for the README

- Setup, supported laptop/OS, tested package versions, required environment names.
- What works live, what is authored/cached, what is simulated, and what is not implemented.
- Attribution for original kit, downloaded art if any, and provider-generated audio rights.
- Actual provider request IDs/timing with secrets removed; no raw camera recordings needed.
- Short video of the full loop, including the verification tell.
- Metrics measured during testing: frame rate, decision latency, TTS start delay, sensor time-to-first-valid, completed runs, invalid proposals rejected. Report actual numbers only.
- No unsupported clinical claims; no claim that a trend identifies fear or that a jump scare caused a specific physiological response.
