# /src/render — James (gameplay & integrator)

Three.js presentation for HUSH: the enclosed shelter, weathered materials, canvas displays, fictional CCTV composition, local animation, equipment picking, close inspection, bounded mouse look and resource disposal. Gameplay authority remains in `src/game/`; React owns controls and captions. See `docs/ASSETS.md` for the runtime inventory and the preserved `lock-in-kit/docs/ASSETS.md` for geometry/node contracts.

- Load all ten GLBs from `public/assets/models`. The room is windowless and solid; the sealed door never opens. There are no gameplay shutters or interior creature reveals.
- `RenderState` is a presentation adapter over authoritative game state. Never invent creature movement, distance, warnings, faults, power state or task progress in a render loop.
- Add `creature_cctv` only to the separate offscreen CCTV scene. `projectCreature` permits a silhouette only on the selected camera's covered graph edge. Unpowered monitors are offline; the sealed containment image requires an actual win.
- Named display meshes are `terminal_screen`, `security_screen` and `proximity_screen`. Generated mesh UVs use bottom-left `(0,0)`; verify canvas/render-target orientation explicitly.
- Door clips `impact`/`dent` move local panels, never the doorway root. Machine clips `fault_01..04` each own their corresponding assembly. Clone per-unit materials before changing indicators. Emergency lever states preserve its fixed locator.
- The current art direction is oppressive near-black industrial horror: corroded charcoal/teal steel, damp streaks, pitting, scratched paint, a small dirty-amber desk pool and a dim red alarm fixture. `weathering.ts` generates original deterministic canvas color/bump/roughness maps at runtime; GLB bytes and kit manifests remain unchanged. The runtime protocol SVG is a documented harder-mode variation with its own updated hash. Keep sufficient local light to recognize equipment and retain the emergency locator during blackout.
- `alarm` comes from authoritative game state. Its light envelope is slow and bounded; reduced motion holds it steady. `scare` identity/time may trigger one brief local impact/feed corruption, never new creature positions. Softer-scare and reduced-motion settings reduce visual intensity. Physical screens must not reveal breach labels or countdowns.
- `onInteract` reports terminal/cameras/equipment clicks on actual GLB descendants. The nearest visible mesh occludes anything behind it; hidden ancestors do not intercept rays. Pointer movement beyond six pixels is a drag, not a click. `inspection` moves closer to the selected console/monitor and returns to the seated position when closed. Accessible HTML controls remain a UI responsibility.
- `SceneView.ready` reports required-asset failures. Repeated `setStation` calls must not erase mouse look. Listener yaw diagnostics follow the actual camera orientation.
- Dispose models, textures, render targets, materials, mixers, event listeners, resize observers and WebGL resources. Scene construction must not make provider requests or read credentials.
- Run render tests and `npm run assets:validate` after asset/animation changes. Parser tests do not replace inspecting actual rendered game screenshots.
- The basement door left of the desk is the shared cutscene prop `src/cutscene/props/basementDoor.ts`, weathered like the room. `RenderState.locks` lights its four lamps green and slides its bolts; `doorMotor` turns the beacon after the last decoy. Cables, the wall tray and the protocol card sit clear of it.
