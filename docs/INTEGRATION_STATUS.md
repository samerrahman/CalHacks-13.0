## Ordered checks and local configuration

The required sequence is native isolation → complete playable offline game → Gemini → ElevenLabs → real sensing → SpacetimeDB. Run only the relevant stage, after its prerequisites:

```sh
npm run native:smoke
npm run integrations:check -- --only=native
npm run test:desktop
npm run integrations:check -- --only=gemini --live
npm run integrations:check -- --only=elevenlabs --live
node electron/smokeLiveProviders.mjs --live
# One bounded contextual dialogue request, followed by exact-caption speech:
node --import tsx electron/liveMonsterCheck.ts --live --narrative-check
# Deliberate live webcam selection and calibration in Electron
npm run integrations:check -- --only=spacetime --live
```

`integrations:check` defaults to native import only. Provider stages require explicit `--live`; there are no automatic retries. Gemini performs bounded model lookup and one structured request. ElevenLabs verifies the configured voice/model and requests one exact authored caption. These two live stages can consume normal account quota. The SpacetimeDB check connects only to the configured database, creates one consenting smoke session, checks its capability gated judge view, and attempts deletion in `finally`. It never publishes a module or changes configuration.

`test:desktop` uses the child-process-only `HUSH_OFFLINE=1` gate: all provider/camera credentials are disabled inside that launched process, remote trace is skipped, and local judge sharing remains available. It never edits `.env`. Normal desktop launch keeps user configuration. Actual configured-model game evidence is written to `docs/qa/lock-in-electron-live-providers.json`; `--alternate` writes a separate `-alternate` result. The successful 3.5 run used only a process override. Actual offline desktop evidence uses `lock-in-electron-smoke.json`. Evidence claims are based on completed results, not driver existence.

Configuration names: `PRESAGE_API_KEY`, `GEMINI_API_KEY`, `GEMINI_MODEL`, optional `GEMINI_DIALOGUE_MODEL`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL_ID`, `VITE_SPACETIMEDB_HOST`, `VITE_SPACETIMEDB_DB_NAME`. Provider keys never use a `VITE_` prefix and never enter the renderer. The SpacetimeDB host and database name are public and may be bundled. Static-hosted browser provider calls currently use local fallbacks; the SpacetimeDB module handles trace storage, not AI or speech secrets. Local `npm run dev` instead uses a Node-side loopback middleware bridge with same-origin/host checks, a custom application header, bounded JSON bodies, rate limits, request deduplication and an exact authored-caption allowlist. Contextual monster generation uses its separate validated route; it does not weaken the authored-speech allowlist. Restart Vite after this change or environment changes. `HUSH_OFFLINE=1` disables that process’s provider credentials without editing environment files.

## Native sensing and local pulse report

The renderer uses installed `SmartSpectraSDK.useMediaStream`, `PULSE_RATE` and the actual protobuf decoder. The restricted camera bridge sends frames to the SDK in main and keeps the Presage key there. Camera & pulse setup provides device selection, mirrored local preview, warmup/calibration progress, recalibrate and stop controls. The preview is the exact controller-owned stream, not a second capture. Mocked lifecycle tests verify selected-device constraints, no browser-only capture, teardown on SDK startup failure and pending-capture disposal; they are not live pulse evidence. An older agent inventory reported zero devices, while the user's newer report confirms a completed 30-second baseline. The current hardware result is user-reported; the latest SDK gate and stale-capture corrections have automated coverage but no new agent-run capture.

Capture is opt-in from setup or the in-game camera dialog, requests video only, disables SDK diagnostic telemetry, and stops on ordinary pause, hiding the app, exit, disposal or permission loss. Deliberately enabling camera calibration in its dialog holds game time paused while allowing calibration; closing the dialog resumes play and preserves its baseline. Live measurements use provider processing; this does not imply the entire measurement pipeline is offline.

The generated SDK defines measurement timestamps in epoch microseconds. The adapter maps their age onto the local monotonic clock and rejects missing, non-finite, excessively future or more-than-five-second-old measurements. Pulse requires the documented 12-second warmup, supported 40–110 BPM range, provider `stable=true`, and native confidence at least 40/100. Breathing independently requires 30 seconds of warmup, supported 5–40 breaths/minute, `stable=true`, and confidence at least 45/100. The former blanket 80 gate was corrected to the installed SDK's metric-specific floors. Chest-only validation code 7 blocks breathing but does not invalidate otherwise eligible pulse; face, lighting, motion, frame-rate, missing and unknown validation still block both. These are eligibility checks, not an accuracy percentage or physiological interpretation. No confidence value is invented, and repeated delivery of the same measurement cannot advance baseline duration. See [the source-backed sensing diagnostics](../src/sensing/DIAGNOSTICS.md).

A baseline requires 30 seconds of usable measurement time and then stays frozen for the run. Elevation is at least +8 BPM sustained for 12 seconds; recovery is below +4 sustained for 12 seconds, with 20 seconds between accepted transitions. Missing/rejected/stale data becomes UNKNOWN. In the current number-line rules, accepted non-manual elevation can add at most eight points to fictional danger and select the capped memory tempo when playback begins. It does not force a movement step, satisfy the attack's audible-evidence gate by itself, cancel an earned lure or undo an already committed strike. The old eight-metre graph-chase rule is superseded; see [current balance formulas](BALANCE.md).

`SensorView.sampleAtMs` is the actual mapped measurement time, not the callback clock. `captureSegment` changes on each capture start/resume; pause discards continuity. Optional local report recording independently requires consent and deduplicates measurement timestamps. Its pulse samples, baseline and report never enter Gemini, ElevenLabs, SpacetimeDB or the judge trace. Deletion clears that in-memory history. See the report UI and root report documentation for exact aggregation and disclosure; no emotional or medical interpretation is attached to the graph.

## Provider and trace boundaries

Gemini receives only finite public observations, authored event types/details and the current allowed tactic/target/taunt sets. Number-line observations add `linePosition`, `lineLength`, `danger` and `quietChargesRemaining`. The display detector's sample clock, movement RNG, wire solution and raw physiology stay private. `MONSTER_STEP` details retain only bounded arithmetically consistent from/to/step values; wire success, timeout and isolation-exhaustion events carry no arbitrary detail. It returns exactly `requestId`, `stateVersion`, `tactic`, `target`, `evidenceEventIds`, `reasonCode`, `tauntId`. Core checks the entire shape, current state, allowed pair, supported evidence/reason, taunt eligibility, expiry and duplicate status before applying only a temporary bias of at most ±0.15. It cannot command a position, step, probability or timer. The shared eight-second budget never pauses gameplay. A failed or late call leaves deterministic local behavior authoritative. Configured 3.8 Flash uses documented LOW thinking with 1024 output tokens and no deprecated sampling override; supported 3.5 Flash-Lite uses MINIMAL when selected.

Monster dialogue has a separate `requestMonster` pipeline. Its request contains only `requestId`, projected public `context`, a finite `fallbackId` trigger and a wall-clock `expiresAtMs`. Gemini returns a structured single sentence plus one to three actual public evidence IDs. Server validation checks exact shape, request identity, bounded length, evidence, and prohibited operative/biometric or obviously false movement claims. The prompt defines the stationary player and outside creature; it cannot read private puzzle answers or pulse measurements. The validated sentence goes directly to ElevenLabs in the same trusted process, and that exact caption is returned with the audio. The renderer cannot submit arbitrary generated text to the speech route. Native and local-development transports implement this contract. Static browser hosting currently uses authored and local fallbacks because provider secrets have not been moved to a trusted remote service.

Dialogue defaults to the approved `gemini-3.5-flash-lite` with MINIMAL thinking, independently of `GEMINI_MODEL`; `GEMINI_DIALOGUE_MODEL` is an optional explicit override. Text generation gets five seconds, and the complete text-plus-speech pipeline gets twelve seconds, further bounded by caller expiry. One monster request is admitted per eighteen seconds per transport, with no automatic retries. The result independently labels `textSource` (`gemini` or `authored-fallback`) and speech source (`elevenlabs`, `cached`, or `fallback`). If Gemini fails, a named authored fallback may still receive real ElevenLabs audio. If speech fails, a genuinely generated caption remains available. Neither case is mislabeled as complete live generation.

Supervisory instructions continue to use exact authored dialogue and the configured authorized voice. A successful real speech response populates a bounded in-memory cache keyed by voice/model/caption/format/settings, never API keys. It starts empty; new responses are LIVE and reused responses are CACHED. It stores at most 32 entries, 2 MB encoded audio per entry and 16 MB total; worker restart may discard it. Expired captions are rejected before lookup and while streaming. The UI reserves speech order when requested, waits for the active instruction to finish, and displays captions from the actual audio-start event. Game state, pause, stage and equipment are rechecked before playback. Creature dialogue follows the exterior creature position and remains eligible when equipment is isolated. The initial safety instruction also survives early isolation so it finishes naturally. Later unpowered radio instructions stop. The first proximity alarm requests contextual FIRST_APPROACH generation; later taunts use the same bounded pipeline. Missing or failed speech leaves captions and original effects available.

New offline tests cover exact generated-caption TTS handoff, configured dialogue model/default selection, hidden-field removal, invalid output/evidence rejection, explicit authored fallback labels, voice outage with valid Gemini text, cancellation at caller deadline, previous-run discard, and route rate/deduplication/offline gates. The actual Chrome test verified the opening instruction stayed visible with one speech start while the generated monster response waited; only after the instruction finished did the creature caption and second speech start appear.

Trace sharing has separate consent. The active SpacetimeDB module stores current number-line position, line length, rounded danger, remaining isolation charges, projected creature movement, tactic and target, and coarse sensing source/quality/trend/age. It stores no raw pulse, private puzzle sequence or wire solution, camera frame, local report or baseline BPM. Private tables are visible only to reducers and the database owner; a view takes a random judge capability and returns one matching trace. Owner and judge capabilities are separate random values, event batches deduplicate on sequence, and a scheduled reducer deletes each session after 24 hours. Stopping trace immediately closes local publication even if remote deletion is unavailable; failed remote deletion is reported. This module has passed local type and web builds but has not been published or checked against Maincloud. The earlier Convex authorization tests and deployment records remain historical evidence.

The Electron shell retains `lockin://app`, restricted navigation, content policy, sandboxing, context isolation and no renderer Node integration. Its IPC and local provider paths also retain their pre-rename names. The judge window has no privileged preload. IPC accepts only the main application's top-level frame. Signing, notarization and an installer are outside this laptop build.
