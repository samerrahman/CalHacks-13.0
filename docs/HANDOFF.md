## Current behavior

- One seeded integer position on a 0–24 line drives monster location, sound, camera coverage and the sampled detector. Discrete moves occur every2.5seconds and are capped at3units. Mistakes, elapsed time, isolation use and accepted baseline-relative pulse elevation influence the probability distribution. Providers may only contribute a bounded temporary bias.
- A25-second grace period precedes movement. The run expires after300active seconds; pause freezes the clock and guided practice is nonlethal. The detector samples every4seconds and is completely dark while equipment is off. Nearby audio/captions remain available. An attack cannot commit until at least2.5seconds after the near alarm; late isolation cannot cancel commitment.
- Four isolation cells each buy up to10seconds with equipment disabled. Each use adds4persistent danger and a10-second cooldown follows restoration. Isolation changes the retreat probability; position still updates only on the2.5-second movement clock. Progress is saved, the overall deadline keeps running, and isolation is not guaranteed safety. Blackouts can be restored without spending a cell.
- Each8/12-fault stage ends with a four-cable matching board. Pointer dragging and keyboard-accessible source/socket selection use the same validated action. Wrong links add mistake pressure. Memory remains5/6cues with faster flashes and a16-second entry window. Earned intermediate lures last12seconds; final containment requires the far endpoint and a three-second seal.
- Speech remains serialized through the existing scheduler. The initial grace prevents early monster interruptions. Monster text may be generated by Gemini, then spoken by ElevenLabs; generated text and authored fallback have distinct labels.

Defaults, the complete weight formula and simulation assumptions are documented in [BALANCE.md](BALANCE.md). Runtime tuning lives in `src/game/config.ts`; archived kit rules do not describe this revision.

## Vitals diagnosis and correction

Three concrete code problems were corrected: the app's blanket80confidence gate rejected SDK-stable pulse/breathing; chest-only validation also invalidated pulse; and recoverable timestamp ordering/gap errors could shut down native capture. The gate now honors the installed SDK's metric-specific stable floors40/45, applies chest warnings only to breathing, and drops known transient timestamp errors while preserving terminal failures. Relevant validation still neutralizes current input. Fresh accepted history can survive a framing flicker, while stale data does not drive danger.

Pulse and breathing merge independently. They keep their separate12/30-second warmup windows and5-second freshness bounds. Local diagnostics now include per-metric confidence, eligibility, measurement/receipt age, cadence and sample count. The corner monitor explains missing breathing instead of silently displaying a dash. See [sensing diagnostics and primary sources](../src/sensing/DIAGNOSTICS.md).

The user reports successful30-second calibration. **A new real-camera measurement session was not performed for this revision.** Hardware reliability is therefore not claimed verified. The older CAMERA_NOT_FOUND result is historical and does not describe the user's currently working camera.
